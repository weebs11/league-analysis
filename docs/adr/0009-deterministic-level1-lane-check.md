# ADR-0009: The Lane Check is deterministic arithmetic, and ability damage is out of scope

**Status:** Accepted (2026-08-23)

## Context

The in-game view needed an every-lane "who starts ahead at level 1?" read, available the
moment a game is detected — before, and independent of, the AI Game Plan. The explicit
requirement: **not** generated by a model. That rules the coach out by design, but the data
source still had to be chosen, and the obvious ambition — comparing level-1 *ability damage*
— had to be tested against what Riot actually publishes.

Findings from the live Data Dragon payloads (2026-08-23, patch 16.16):

- **Base stats are complete and reliable.** `champion.json` carries the full stat block
  (hp, attackdamage, attackspeed, armor, spellblock, attackrange, movespeed, regen, mana)
  plus per-level growth for every champion. The app was already downloading this file and
  discarding the stats at index-build time.
- **Ability damage is not publishable data.** Older champions expose spell numbers via
  `effectBurn`, but modern kits (checked: Caitlyn, Briar, Ambessa) ship tooltips whose
  placeholders (`{{ initialdamage }}`, `{{ calc_damage_1_max }}`) reference data values
  resolved inside the game engine and absent from Data Dragon — `effectBurn` is all zeros.
  There is no patch for which every champion's spell damage can be read from Riot's CDN.
- **Rank-1 cooldowns and costs *are* reliable** (`cooldown`/`cost` arrays in the
  per-champion files) — the app already uses the cooldowns for coaching threat cards.
- **Community Dragon's `champion.bin.json`** does hold the real numbers, but as per-champion
  spell-calculation trees (`mSpellCalculations`, formula parts, char-level interpolations)
  that stat sites hand-curate around. Parsing it generically is a project of its own and
  fragile per patch; rejected.

## Decision

**`src/lanecompare.js` computes the Lane Check as pure arithmetic over Data Dragon base
stats**, served by `GET /api/lanecompare` from the current game snapshot:

- **Champion index entries keep Riot's `stats` block** (previously discarded in
  `ddragon.init()`), so the comparison is synchronous, current-patch, and works offline from
  the primed cache. The same block feeds the Champion Database's Base Stats card.
- **Lanes pair by role label** (`Top` … `Support`, as gamestate emits them); champions whose
  role data is blank or duplicated fall back to list-order pairing so nobody silently
  disappears from the view.
- **The verdict is a weighted score over derived metrics** — auto-attack DPS (AD × AS),
  effective HP vs physical/magic (HP × (1 + resist/100)), attack range, HP regen, move
  speed — with relative diffs clamped so no single stat can decide alone, and raw stats that
  feed a derived metric weighted at zero so nothing is counted twice. Same input, same
  output, byte for byte (asserted in tests).
- **Ability damage is explicitly out of scope; rank-1 cooldowns and costs are in.** The UI
  says so in one honest sentence rather than pretending abilities don't exist. If ability
  numbers are ever wanted, the recorded path is a Community Dragon `champion.bin.json`
  parser behind its own adapter (the ADR-0008 pattern), not tooltip scraping.

## Consequences

- The Lane Check needs no API key, no network beyond the already-cached patch data, no
  cache of its own, and can never disagree with Data Dragon — every number is verifiable by
  hand against the champion's stat sheet.
- The verdict is honest about what it is: a stat-sheet head start, not a matchup analysis.
  Kit-driven level-1 monsters (e.g. strong level-1 passives) will read as "even" — that
  nuance stays the Game Plan's job, and the UI copy frames it that way.
- The metric weights are judgment calls. They live in one `METRICS` table with the verdict
  thresholds beside it; tuning is a one-file change with no data migration.
